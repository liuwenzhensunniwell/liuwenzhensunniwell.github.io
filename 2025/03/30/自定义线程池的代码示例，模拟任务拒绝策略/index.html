自定义线程池的代码示例，模拟任务拒绝策略

发表于2025-03-30|更新于2025-03-30
|阅读量:

自定义线程池的代码示例，使用 Java 的 ThreadPoolExecutor，并实现一个简单的 任务拒绝策略 模拟。代码会清晰展示线程池的核心参数配置、自定义拒绝策略，以及运行效果，适合你在面试中展示对线程池的理解。

代码解析

1. 线程池参数

corePoolSize = 2：核心线程数，始终保留2个线程。
maximumPoolSize = 4：最大线程数，允许扩展到4个线程。
workQueue = ArrayBlockingQueue(3)：任务队列容量为3。
keepAliveTime = 5秒：非核心线程空闲5秒后回收。
总容量：核心线程(2) + 队列(3) + 额外线程(2) = 7个任务。超出7个任务会触发拒绝策略。

2. 自定义拒绝策略

  • CustomRejectedExecutionHandler：
  • 实现 RejectedExecutionHandler 接口。
  • 使用 AtomicInteger 记录拒绝次数。
  • 打印被拒绝的任务信息，模拟简单处理（实际可扩展为存入数据库或重试）。
  • 触发条件：提交10个任务，超过7个（2+3+2）时，后续任务被拒绝。

3. 任务执行逻辑

  • Task 类：每个任务打印开始和结束信息，睡眠1秒模拟耗时。
  • submit 方法：将任务提交到线程池，超出容量时触发拒绝。

4. 关闭线程池

  • shutdown()：等待任务完成。
  • awaitTermination()：超时后强制关闭。

面试要点记录

1. 线程池工作原理：

  • 先用核心线程 -> 队列满了 -> 创建额外线程至最大值 -> 超出则拒绝。

2. 拒绝策略触发：

  • 当任务数 > (corePoolSize + workQueue.capacity + (maximumPoolSize - corePoolSize))。
  • 示例中：10 > (2 + 3 + 2) = 7，所以拒绝3个任务。

3. 内置拒绝策略：

  • AbortPolicy：抛异常（默认）。
  • DiscardPolicy：无声丢弃。
  • DiscardOldestPolicy：丢弃队列头部任务。
  • CallerRunsPolicy：调用者线程执行。

4. 自定义策略：

  • 可记录日志、存入备用队列、延迟重试等。

扩展练习

  1. 修改队列：将 ArrayBlockingQueue 改为 LinkedBlockingQueue，观察拒绝策略是否触发。
  2. 增强拒绝策略：在拒绝时将任务存入 List，模拟重试机制。
  3. 动态调整：用 setCorePoolSize 或 setMaximumPoolSize 动态改变线程池大小。

记录建议

  • 手写代码：记下 ThreadPoolExecutor 的构造方法和参数含义。
  • 画图：
    • 画一个线程池结构：2个核心线程 -> 3个队列槽 -> 2个额外线程 -> 拒绝区域。
    • 标注任务分配和拒绝点。
  • 口述：
    “我自定义了一个线程池，核心线程2个，最大4个，队列3个，超出7个任务时用自定义拒绝策略记录拒绝次数。”
